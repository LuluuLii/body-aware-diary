> 目标：为 body-aware-diary 的下一轮功能收敛提供决策依据。

> 方法：WebSearch 汇总 + 现有产品公开信息交叉验证。
> **未包含截图**：本轮受网络工具权限限制未下载 App Store 截图。每个产品段末给出参考链接，需要视觉参考请打开对应链接。

## 一、我们的定位假设

主流健身 App（Strong / Hevy / FitNotes）是 **"动作 × 组数 × 重量" 的会计视角**——适合撸铁，不适合瑜伽、普拉提、游泳、网球、芭蕾这类 **神经-身体觉知运动**（训练神经系统对身体的精细感知与控制，对应 proprioception / motor control）。

我们的核心洞察：这类运动的本质是训练"我能否精细地感知并控制我的身体"。记录感受本身就有疗愈作用。所以我们做的不是"瑜伽版 Strong"，而是**身体觉察日记**。

已拍板：
1. **主场景**：课后 5 分钟快速记录；深度反思发生在回顾时
2. **不做 AI 对话**（增加成本、不符合"感受 > 分析"的调性）；未来可能做"沉默的图书管理员"（拍照/描述 → 找到体式名）
3. **动作/体式非必选**
4. **知识库改造为"个人身体图鉴"**：系统内置 + 用户导入的动作库，从记录反向跳转
5. **补充入口**：睡前身体扫描、晨起感受（非运动场景的觉察）
6. **不做社交、streak、徽章**——这些会把练习变成表演

## 二、结论摘要（TL;DR）

以下 5 条是**可以直接映射到我们下一步产品动作**的洞察：

1. **"多维日记 + 回顾时的相关性揭示" 是最值得抄的骨架**（源自 Bearable）
   我们的记录不应止于"今天做了什么、感觉如何"，而应是**多个可勾选维度**（体式、身体部位感受、能量、情绪、睡眠、外部因素），回顾页面自动跑出 "你的左髋在 10 次记录里出现 7 次" 这种 correlation。这是 body-aware-diary 从"日记"变成"镜子"的关键。

2. **录入 UX 必须 < 30 秒**（源自 Daylio）
   Daylio 用 5 档表情 + 图标网格实现了极低摩擦。我们的 record 页也必须遵守这个原则——**任何超过 30 秒的默认路径都是设计失败**。深度输入（长文本、多图）永远是可选的次级路径。

3. **感受词汇需要"空间选择器"，而不是标签云**（源自 How We Feel）
   How We Feel 的 Mood Meter 用 "能量高低 × 愉悦度" 的四象限拆分 144 个情绪词，帮用户"找到"精确的感受词。我们的身体感受也应该有类似的空间化选择——例如"紧 / 松" × "热 / 凉" 或 "深 / 浅" × "稳 / 抖"，避免让用户在一长串标签里翻找。**关键**：他们 2025 年 6 月上线了"生理感受"追踪（tight chest, fluttering stomach），这直接印证了我们的方向。

4. **语气基调决定用户会不会回来**（源自 Finch）
   Finch 被反复称赞的不是功能，是"compassionate rather than preachy"。我们要在每个文案节点（空态、提示、回顾摘要）用**观察式而非评判式**的语言——"你左肩连续 5 天出现张力"，不是"注意你的左肩问题"。

5. **AI 的正确用法是"prompt scaffold"，不是"chat"**（源自 Reflectly 的正反经验）
   Reflectly 号称 AI，实际只是精心设计的 prompt 序列——用户满意度依然不错。这印证了我们的判断：**不需要真 AI，需要好的引导式提问结构**。例如回顾页固定问 3 个引导："这周你的身体最像什么？"、"哪个部位在提醒你？"、"下周你想给自己一个什么练习？"

## 三、各产品详解

### 1. Bearable ⭐（最重要参考）

**一句话**：为慢病患者做的多维度症状追踪 + 长期相关性洞察工具。

**为什么最重要**：它是六款产品里**唯一把"多维记录 → 长期看见模式"这个闭环做扎实**的。慢病用户和"想觉察身体"的用户在数据结构诉求上高度重合——都需要在时间线上追踪"多个变量之间的关系"。

**核心机制**：
- **多维度录入**：一次 check-in 可以同时勾选 mood、emotions、sleep、symptoms、energy 各自的等级
- **无限自定义指标**：用户可以创造自己关心的追踪维度（"左肩紧张"、"睡前思绪多"等）
- **"Impacts" 面板**：这是核心杀手锏——展示每个习惯/因素对每个健康指标的影响权重（correlations），帮用户看到"睡眠<6 小时的日子，午后能量下降 40%"这样的模式
- **周报**：不用户主动回顾也会周期性推送模式
- **免费 tier 已足够可用**，付费 ($34.99/年) 解锁 goals、experiments、超过 30 天的历史数据

**可借鉴的具体 UX 模式**：
- **快速录入 = 复选，不是自由文本**：Bearable 的日 log 就是快速勾选一组预设，我们的"课后 5 分钟"必须效仿
- **"Impacts" 语义借鉴到我们的回顾页**：不告诉用户"你有问题"，只呈现"X 出现时 Y 常常 Z"——把解读权还给用户
- **用户自定义指标**：这是"个人图鉴"的重要一环，用户应能新增自己的体式、自己的感受词

**应避免的反模式**：
- Bearable 的密度过高——它面向的是慢病用户（愿意每天多次录入），我们的用户不是。要在 **多维度支持** 和 **默认极简** 之间找平衡：**默认最少 2 个字段（部位 + 感受），其他维度可展开**。
- Bearable 有 goal / experiment 功能，容易把日记变成任务。我们不做。

参考：[bearable.app](https://bearable.app/) · [App Store](https://apps.apple.com/us/app/bearable-symptom-tracker/id1482581097)

### 2. Daylio

**一句话**：用图标 + 5 档表情把情绪日记摩擦压到 < 30 秒的开创者。

**核心机制**：
- **5 档情绪 + 图标化活动**：整条录入不需要打字。图标是用户自定义的（皮肤、颜色都可以调）
- **可选深化**：想写就写、想拍就拍、想录音就录音——**不逼迫**
- **可视化**：Year in Pixels（一年 365 格的马赛克）、月历、"Influence on Mood" 图（隔离某活动看它对情绪的统计影响）
- **本地存储 + 100% 私有**：不上云是营销重点
- **2026 新增**：录入时给触感反馈（haptic feedback）

**可借鉴的具体 UX 模式**：
- **表情/图标是感受输入的最优载体**。SensationPicker 应该继续走图形化路线，避免让用户敲字
- **Year in Pixels 是"看见自我"的杀手锏可视化**——一年的身体感受浓缩到一屏，用色块编码。我们可以做"365 天身体地图" 或 "365 天感受色卡"，作为回顾页的核心视觉
- **"Influence on Mood" 语义 = "Influence on Body"**：让用户选一个活动（"上瑜伽"），看它对身体感受的统计影响
- **触感反馈** 是低成本高回馈的细节——每次点选感受词给一次轻微 haptic，会让人有"我记住了"的确认感（微信小程序端 Taro 可用 `wx.vibrateShort`）

**应避免的反模式**：
- **Streak 显示**：Daylio 有连续记录天数展示，会让人在没状态的日子也强迫打卡——违背"觉察 > 打卡"的调性
- **成就徽章**：同样问题
- **过度分析视图**：Daylio 有些统计页面对普通用户过重，我们回顾页要克制

参考：[daylio.net](https://daylio.net/) · [App Store](https://apps.apple.com/us/app/daylio-journal-mood-tracker/id1194023242)

### 3. How We Feel

**一句话**：耶鲁情商中心背书的情绪 check-in 工具，用"能量 × 愉悦度"象限帮用户找到 144 个精确情绪词。

**为什么关键**：**它是六款产品里唯一把"帮用户找到词"当作核心问题的**。这正是我们要解决的——瑜伽/普拉提用户"说不出刚才那个感受"的问题，本质是找词困难。

**核心机制**：
- **Mood Meter 网格**：2×2 象限（高能量-高愉悦 / 高能量-低愉悦 / 低能量-高愉悦 / 低能量-低愉悦），每个象限内展开 36 个词，共 144 个
- **check-in 流程**：选感受 → 标注影响因素 → 可选写日记
- **2025-06 新增**：物理感受追踪（"tight chest"、"fluttering stomach"）——**这是他们意识到情绪要下沉到身体感受的信号，直接印证我们的方向**
- **短视频 (< 2 min)**：给出"改变思维 / 动一动身体 / 保持觉察 / 联系他人"这四类调节策略
- **朋友分享功能**（我们不做）

**可借鉴的具体 UX 模式（重点）**：
- **象限选择器直接适配到"身体感受"**：
  - 我们可以做 **"松-紧" × "深-浅"** 或 **"稳-抖" × "热-凉"** 的 2×2 空间选择器
  - 用户先点象限，展开该象限的精确词汇（"松弛 / 舒展 / 沉重 / 空"）
  - 比现有 SensationPicker 的平铺标签更符合直觉
- **"物理感受" 就是我们要做的**：他们已经验证了这个需求存在
- **check-in 步骤感**：象限 → 精确词 → 可选影响因素——比"一屏塞所有字段"更适合快速录入

**应避免的反模式**：
- 他们的视频教育内容让 app 变重——我们不做这类内容
- 朋友分享把私密觉察社交化——我们坚决不做

参考：[howwefeel.org](https://howwefeel.org/) · [App Store](https://apps.apple.com/us/app/how-we-feel/id1562706384)

### 4. Finch

**一句话**：温柔的自我关怀 App，用宠物养成让用户"觉得被关心"。

**核心机制**：
- 养一只小鸟 Finch，完成 self-care 任务给它喂食
- 心情 check-in、呼吸练习、日记 prompt、CBT 式反思
- **核心不是玩法，是语气**：反复被用户称赞"compassionate rather than preachy"

**只学 tone，不学玩法**（重要说明）：
- **玩法反模式**：宠物养成 = 游戏化 = 转移了觉察本身的注意力。我们坚决不做
- **Tone 的可借鉴之处**：
  - **观察式，非评判式**：说 "你左肩连续 5 天出现张力" 而不是 "注意你的左肩"
  - **不预设正确答案**：说 "你今天想给自己什么？" 而不是 "试试冥想"
  - **不推销练习**：不做"每日必练"提醒
  - **在用户空白时不 push**：用户几天没录入，不发"想念你"这类推送——沉默是尊重

**具体文案参考**（我们要写的空态/回顾文案，可以对照 Finch 的调性）：
- ❌ "记录一下今天的练习吧！"
- ✅ "今天想留下什么？"
- ❌ "你已经连续 7 天记录，太棒了！"
- ✅ "过去 7 次记录里，你的右膝出现了 3 次。"

参考：[App Store](https://apps.apple.com/us/app/finch-self-care-pet/id1528595748)

### 5. Reflectly

**一句话**：号称 AI 的引导式日记 App，实际是精心设计的 prompt 序列。

**为什么值得看**：它印证了我们的核心判断——**用户想要的不是 AI，是好问题**。

**核心机制**：
- 每日 prompt 序列走完 "发生了什么 → 感觉如何 → 想做什么"
- 声称 AI 会基于历史提问，实际是模板 + 用户输入的关键词组合
- 每日"挑战"（画一幅画、说三句肯定的话等）
- 语音输入、图片上传

**可借鉴的具体 UX 模式**：
- **回顾页的引导问题**（不需要 AI，模板即可）：
  - 每周 review 弹出 3 个固定问题：
    1. "过去一周你的身体最像什么？"（隐喻式，避免评判）
    2. "哪个部位在提醒你？"（把感受人格化，减少防御）
    3. "下周你想给自己一个什么练习？"（不是 goal，是 gift）
- **回顾时的 recap 是模板文本 + 用户数据填空**，不需要 LLM：
  - "过去 7 天，你记录了 X 次身体感受，其中 [部位] 出现最多。"

**应避免的反模式**：
- **AI 卖点**：Reflectly 的 AI 定位其实招来了不满评价（"noping AI actually works"）——我们不做 AI 就不要打这个标签
- **Streak / daily challenge**：又是打卡逻辑，跳过
- **付费墙陷阱**：Reflectly 因订阅纠纷用户信任度受损——我们付费策略要明确、诚实

参考：[App Store](https://apps.apple.com/us/app/reflectly-journal-ai-diary/id1241229134)

### 6. 瑜伽/普拉提体式库参考（Down Dog / Alo Moves / Pocket Yoga）

这三款都不是"日记"产品，我们看它们的**体式分类学**。

**Down Dog**（算法生成派）：
- 60,000+ 配置组合
- 用户维度：style（Vinyasa / Hatha / Yin / Restorative / Ashtanga / Gentle / Chair / Hot 26...）+ level + duration + focus area（19 个身体部位）+ music + voice
- 一个订阅覆盖 Yoga / HIIT / Barre / Pilates / Prenatal Yoga / Meditation

**Alo Moves**（内容派）：
- 名师课程，高质量拍摄
- 分类主要按老师、风格、难度

**Pocket Yoga**（工具派）：
- 动画 + 语音，比 Down Dog 便宜
- 有独立的体式索引

**可借鉴的具体 UX 模式**：
- **Down Dog 的"19 个身体 focus area"直接映射我们的动作 → 部位关联**
  - 用户点击"课后 5 分钟"记录 → 快速勾选"我主要练了哪些部位" → 系统提示"这些部位常涉及 [体式列表]"
  - 用户选中体式 → 补全为完整记录
  - 这样解决了"新手记不住体式名"的核心痛点
- **体式的三级分类学**（我们可以采用）：
  1. **体式家族**：站立 / 坐姿 / 俯卧 / 仰卧 / 倒立 / 平衡 / 扭转 / 后弯 / 前屈
  2. **主要肌群**：肩 / 核心 / 髋 / 背 / 腿 / 全身
  3. **强度**：柔和 / 中等 / 挑战
- **Pocket Yoga 的动画式呈现** 比静态图更有传达力——我们体式卡片可以用循环动图（GIF/APNG），带停留感

**应避免的反模式**：
- **Alo Moves 的订阅重内容路线**：不适合我们
- **Down Dog 的"生成一节课"逻辑**：我们不是教练类产品，不做 practice generation
- **让用户 pick 30 个字段**：Down Dog 起始配置太重，我们要极简默认 + 可展开

参考：[downdogapp.com](https://www.downdogapp.com/) · [alomoves.com](https://www.alomoves.com/) · [pocketyoga.com](https://www.pocketyoga.com/)

## 五、需要警惕的反模式（红线清单）

以下都是这些产品做了、但**不适合我们的定位**，明确不做：

1. ❌ **Streak / 连续打卡计数**（Daylio、Reflectly、Finch）——违反"觉察 > 打卡"，会把练习变成表演
2. ❌ **徽章 / 成就系统**（Finch、Reflectly）——同上，且让用户注意力从身体转移到系统奖励
3. ❌ **游戏化（宠物养成、任务系统）**（Finch）——刻意可爱，与"疗愈感"是两回事
4. ❌ **AI 聊天 / 智能建议**（Reflectly）——我们不预设正确答案，只呈现事实
5. ❌ **社交分享**（How We Feel、Finch）——觉察本质私密，不社交
6. ❌ **推送提醒"你已经好几天没记录了"**（Reflectly、Finch 部分场景）——沉默是尊重
7. ❌ **教育内容 / 视频课**（How We Feel、Alo Moves）——我们不做知识灌输
8. ❌ **付费墙纠缠**（Reflectly 的差评来源）——如果做订阅要极其克制、透明
9. ❌ **过度可视化图表**（Bearable 密集视图）——回顾要"温柔可读"，不做仪表盘
10. ❌ **强制标签**（部分体式追踪 App）——我们的动作/体式必须是可选的
