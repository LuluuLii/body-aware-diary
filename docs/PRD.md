## 零、语境提示

本 PRD 是**产品定位重启后的第一份完整需求**。v1 已上线的功能（详情见近期 commit 历史）大部分需要重写，不是"新增功能"而是"重构主干"。

**重构的原因**：v1 时期定位偏"通用日记 App"，v2 收敛为"神经-身体觉知运动的身体感知日记"，主轴从"记录事件"改为"记录感受与身体反馈"，因此三个核心组件（record 页 / SensationPicker / BodyMap）都需要从数据结构到 UX 重做。

## 一、范围声明

### 本 Sprint 做什么

**核心闭环**（缺一不可）：

1. **记录**：`pages/record` 单页多维快速勾选 + 渐进式深化 + 30 秒基线
2. **选感受**：`SensationPicker` 从平铺标签改为 2×2 象限 + 精确词
3. **选/找身体位置**：`BodyMap` 升级到肌肉级（30 块主要肌群），支持标注感受
4. **找体式**：反向找体式流（部位 → 体式家族 → 卡片墙），覆盖"记不住动作名"痛点
5. **认识肌肉与体式**：肌肉详情页 + 体式详情页（含发力感线索与代偿点）
6. **仪式感深化**：可上传照片、语音、手写笔记
7. **文案统一改造**：全站观察式语气

**非核心但要顺手改的**：

8. `app.config.ts` 页面结构调整（新增/删除若干路由）
9. 主题色、字号、间距按照最新的"手账美学"方向做一次视觉刷新（细节留给设计稿）

### 本 Sprint 不做（推迟到 v3 或更晚）

- 睡前身体扫描 / 晨起感受入口（P2，XHS 数据未验证需求）
- 年度色卡 / Year in Pixels 回顾视图
- 周回顾模板化引导问题（3 个固定问题）
- 里程课时视图（第 50/100/200 节课深度回顾）
- 相关性 correlation 面板
- 图卡导出到 XHS
- 用户贡献体式（UGC）
- 深层/浅层视图切换、性别版切换
- LoRA 手绘风格插画
- 匿名鼓励卡
- 教培学员专属模式

上述都进 [roadmap](./roadmap.md)（PRD 通过后我写）。

## 二、成功信号（不是 KPI，是我们内部认为的"做到了"标准）

**做到了长这样**：

1. 一位真实用户能在**课后 30 秒内**完成一条包含"部位 + 感受"的记录，无 friction
2. 用户能通过点击身体图上的具体肌肉，标注"这里酸/紧/温/涨/无感"
3. 用户从记录里点击"下犬式" → 能看到该体式激活哪些肌群、发力感、常见代偿
4. 用户从记录里点击某块肌肉 → 能看到常激活该肌肉的体式列表
5. 用户能上传一张练习后的照片作为记录附件
6. **访谈 5 位真实用户**，他们能说出至少 2 个和当前 v1 不同的、能让他们回来的理由
7. 全站没有任何一个文案带评判/催促语气

**明确不做的成功信号**：DAU、留存率、GMV。不是不看，是本 Sprint 不作为决策依据。

## 三、核心用户故事

按优先级排列。每条故事包含："作为...我想...这样..."结构 + 核心验收标准。

### US-1：课后 5 分钟快速记录（P0）

> 作为刚上完普拉提课的用户，我想在 30 秒内留下"今天练了核心 + 髋，感觉髋很紧"，这样我不用打开手账本或翻小红书就能存下这次的感受。

**验收**：
- 打开 App → 点击"记录" → 3 tap 内完成一条最简记录
- 默认字段仅 3 个：部位、感受、可选文本
- 完成后有轻柔的"合上本子"反馈（视觉+触感）

### US-2：肌肉级酸痛标注（P0）

> 作为练完普拉提第二天肌肉酸的用户，我想在人体图上点具体肌肉（不是"腿"这么粗）标记"这里酸"，这样过几天翻回来我能看到我练的是哪块。

**验收**：
- 进入"记录 → 展开身体图" → 看到前视/后视人体图
- 点击具体肌肉（如"臀中肌"）→ 弹出感受 tag 选择（酸/紧/温/涨/无感 五档）
- 可以在一次记录里标注多块肌肉

### US-3：从记录反查体式细节（P0）

> 作为在记录里标了"下犬式"的用户，我想点这个体式看到它激活哪些肌肉、正确的发力感是什么，这样我不用问教练也能大致理解今天练的是什么。

**验收**：
- 记录详情页里的体式名可点击
- 跳转到体式详情页，包含四段固定结构：
  1. 主要激活肌群（BodyMap 高亮）
  2. 发力感线索
  3. 常见代偿点
  4. 常见感受词（可 tap 进入记录）

### US-4：记不住体式名时反向查找（P0）

> 作为普拉提新手，我想说"我今天练了肩，教练带的是那种扭转动作"，就能被引导找到候选体式名。

**验收**：
- 记录页里点"体式"字段**直接进入** pose picker（一步，不需要中间按钮）
- picker 页统一有：**搜索框 + 家族 tab + 卡片墙 + 自定义名 兜底**
- 若已选部位（record 页最常见路径）→ picker 默认展示与该部位相关的候选卡片（跨家族，按相关度排）→ **1 步到候选**
- 若未选部位 → picker 默认展示常见基础体式 + 引导按家族浏览
- 每张卡片：体式图（GIF 优选） + 中文名 + 家族标签 + 主要激活肌群（简）
- 支持"我说不出来"—— 允许自定义名（如"教练说的那个扭转"），保存为个人体式

### US-5：了解一块肌肉常在哪些体式激活（P1）

> 作为想主动练髋外展肌群的用户，我想点这块肌肉看到常激活它的体式列表。

**验收**：
- 肌肉详情页有"常激活体式"区块
- 点击体式跳转到体式详情

### US-6：给记录加照片/语音（P1）

> 作为想给这次课留个纪念的用户，我想上传一张镜子自拍或场地照，让这条记录有仪式感。

**验收**：
- 记录页有"上传图片"入口（渐进展开）
- 支持相册选择 + 拍照
- 语音留言（10-60 秒）
- 手写笔记扫描（就是普通拍照）

### US-7：文案不催我、不评判我（P0，横切）

> 作为不想被 App 催促的用户，我希望任何文案都不告诉我"你已经 3 天没记录了"或"太棒了继续加油"。

**验收**：
- 通过全站文案审计清单（下面 § 4.8）

### US-8：第一次使用时被指点"我可以在这里记什么"（P1）

> 作为第一次打开 App 的新用户，我想快速被指点"这里可以记什么"、"BodyMap 怎么点"、"体式详情能看什么"，之后不希望被反复打扰。

**验收**：
- 首次进入 record / 首次点 BodyMap / 首次进体式详情，各出**一屏简短 tips**（见 § 4.9）
- 之后不再显示；可在设置页手动重开
- 全程可跳过，不做强制 walk-through

## 四、页面与流程规格

### 4.1 记录页 `pages/record`（P0，重构）

**入口**：Tab bar "日记" 页的浮动 + 按钮 / 直接跳 `pages/record`

**默认视图（30 秒基线）**：

单页布局，顶部到底部：

```
┌──────────────────────────────┐
│  今天想留下什么？              │  ← 观察式标题
│  2026-07-08 · 第 XX 次        │  ← 累积课时 + 日期
├──────────────────────────────┤
│  [BodyMap 缩略图 · 可展开]     │  ← 触发展开进入肌肉标注
├──────────────────────────────┤
│  [SensationPicker 象限]        │  ← 2×2 象限选感受
├──────────────────────────────┤
│  一句话（可选）                │  ← 单行输入
├──────────────────────────────┤
│  [+ 更多字段]                  │  ← 折叠区
├──────────────────────────────┤
│         记下了                 │  ← 完成 CTA
└──────────────────────────────┘
```

**"一句话（可选）" 的引导策略**（教用户如何记录，符合原则 5 + 原则 11）：

单行输入的 placeholder 采用**首次显式 + 后续轮换**——引导用户逐渐建立"发力感 / 身体反馈"的记录习惯，同时不让老用户审美疲劳：

- **前 3 次记录**（新手期）：固定 placeholder：`记下老师说的发力点，或今天最清晰的感受。`
- **第 4 次开始**（常态期）：随机轮换 hint 池，每次进入 record 页随机取一条：
  - `哪里的发力最清晰？`
  - `哪里最模糊？`
  - `今天想留下什么？`
  - `老师说的哪句话让你有感？`
  - `身体在提醒你什么？`
  - `今天你和身体的对话是什么？`

hint 池可持续扩充；不做 A/B 也不做算法推荐——**随机 + 观察式** 即可。

**"更多字段" 展开后（渐进式）**：
- 体式（可选，点击直接进入 pose picker，见 § 4.6——不做中间按钮）
- **⭐ 发力感 / 老师的重点**（多行文本，本产品最独特的字段）
  - 用途：记录教练指导的发力点，或用户自己领悟的发力感受
  - **自动关联**：如果本次记录选了体式，此条自动挂到该体式下
  - **闭环回顾**：下次进入该体式详情页时，"发力感线索"（系统提供）旁边会显示"我的发力感笔记"（用户过去的这条累积），形成个人图鉴
- 时长
- 照片
- 语音
- 心情
- 外部因素（睡眠/月经期/情绪）
- 手写扫描

**状态机**：
- 空（未填任何字段）→ CTA 灰
- 至少填 1 个字段 → CTA 激活
- 完成 → 合上本子动效 → 跳回日记流并高亮新条目

**边界**：
- 允许"极简一条"：只勾一个部位、其他都空，也是完整记录（原则 10）
- 未完成状态支持自动草稿（App 退到后台不丢）
- 支持"稍后完善"（保存但可再编辑）

**文案清单**（原则 6 观察式）：
- 空态：`今天想留下什么？`
- 完成：`记下了。`
- 保存失败：`没能保存下来，再试一次？`（不用 error 字眼）

### 4.2 `SensationPicker` 组件（P0，重构）

**从**：平铺 20+ 标签的一维列表
**到**：2×2 象限的空间选择器（骨架借鉴 How We Feel Mood Meter · 基于 Russell 1980 *Circumplex Model of Affect*）

**为什么用这个骨架**：把复杂的"整节课感受"降维到两个可感知的维度上，用户不需要在长词汇列表里翻找就能定位自己的状态。

**上下文说明**：SensationPicker 记录的是**整节课/整次练习的整体感受**，一次记录里只出现一次。与之独立的是 **BodyMap 上的肌肉级感受**——那里用 5 tag（酸/紧/温/涨/无感）标注具体肌肉。**两个机制分工清晰**：SensationPicker = 整体读数，BodyMap = 局部读数。

---

**交互流程**：连续坐标点 + 可选感受词补充

---

**Step 1：在坐标系里放一个点**

- 2×2 坐标平面，一屏可见，占屏高约 55-60%
- **X 轴**：**消耗 ← → 滋养** —— 这节课整体是消耗你的、还是滋养你的？
- **Y 轴**：**训练感浅 ← → 训练感深** —— 身体被激活的深度（柔和/未被调动 ↔ 充分激活）
- 四个象限的名字（舒展 / 饱满 / 过载 / 未启）作为**视觉锚点**印在象限背景上，配合森林晨光 / 大地深处双主题的柔和背景色——**不是选择目标，是地图上的地名**
- 用户在坐标系**任意位置** tap 或 drag 放置一个点——**连续位置，不是四选一**
- 点落下后可自由拖动，直到用户确认（无显式"确认"按钮，只要不离开页面就一直可调）
- 若坐标很接近轴线中央，视觉上不做特别处理——用户想"我不清楚"是允许的

**象限布局**（作为视觉锚点，不是选择项）：

```
              ↑ 训练感深
         ┌────────┬────────┐
         │  过载  │  饱满  │
 消耗 ← ├────────┼────────┤ → 滋养
         │  未启  │  舒展  │
         └────────┴────────┘
              ↓ 训练感浅
```

**四个象限的语义 + 典型场景**（用于设计参考，用户不需要读到）：

| 象限 | 位置 | 语义 | 典型场景 |
|---|---|---|---|
| **舒展**（滋养 + 浅）| 右下 | 身体柔和、被温柔照顾 | 一节 restorative / 恢复课 |
| **饱满**（滋养 + 深）| 右上 | 被充分激活、清晰有力 | 一节 breakthrough 的课 |
| **过载**（消耗 + 深）| 左上 | 太狠、边缘、有伤感 | 强度过大、代偿多的课 |
| **未启**（消耗 + 浅）| 左下 | 没进入状态、走神 | 状态不佳的一节课 |

---

**Step 2（可选）：补充感受词**

Step 1 放下点之后，坐标系下方出现"感受词补充区"：

1. **候选词胶囊**（chip UI）
   - 6-8 个胶囊，来自坐标点**最近象限**的精确词池（见下表）
   - Tap 胶囊即选中，选中态用主题色描边；再 tap 取消
   - 最多选 3 个
2. **自由输入框**
   - 单行 placeholder：`或者用自己的话...（可选）`
   - 用户可输入个性化感受词
   - 输入的词自动加入用户个人词库（P1，下次会作为候选优先出现）

**用户可以只放点不选词**——坐标本身就是一次完整记录，符合原则 10「默认极简」。

**候选词池**（按象限，胶囊顺序为该象限最典型的词优先）：

| 象限（视觉锚点）| 候选词胶囊 |
|---|---|
| **舒展**（滋养 + 浅）| 放松 / 舒展 / 通透 / 宁静 / 轻盈 / 微 / 恢复 / 松开 |
| **饱满**（滋养 + 深）| 充实 / 饱满 / 清晰 / 激活 / 突破 / 通电 / 酸爽 / 有力 |
| **过载**（消耗 + 深）| 累 / 酸 / 紧 / 抽 / 颤 / 闷 / 代偿 / 勉强 |
| **未启**（消耗 + 浅）| 无感 / 空 / 麻木 / 拖沓 / 走神 / 浮 / 隔 / 干 |

**候选切换逻辑**：
- 默认展示离坐标点**最近象限**的词池
- 用户移动坐标点跨越象限边界时，候选胶囊会**平滑替换**（旧胶囊淡出，新胶囊淡入；已选中的词若不在新象限词池里，保留选中态但不受下次候选影响）
- 若坐标接近轴线中央（离多个象限距离相近），P2 可优化为混合展示相邻象限的候选，v2 先不做

---

**为什么改成这个交互**：
- **连续 > 离散**：用户的真实感受不是"四选一"，是渐变（比如"稍微有点消耗，但训练感很深"这种细腻描述）。坐标点保留了这种连续性
- **词是补充不是必需**：坐标本身已经是完整数据；词是可选深化——避免用户"必须找到一个词才能完成记录"的摩擦
- **胶囊 + 自输**：既支持快速点选，也允许用户用自己的话，符合原则 5（仪式感）+ 原则 11（图形 > 文字，但也不阻断文字）
- **象限词消失在象限内部**：坐标系视觉更干净，象限只作视觉锚点——像看地图，不像看菜单

---

**扩展**（P1）：
- 用户自输的词入个人词库，下次作为候选优先出现（"你常说的词"区块）
- 用户可在个人词库里调整某词的象限归属
- 支持在坐标点上添加短评论（不同于全局的"一句话"字段——这个是专门附着在坐标点上的备注）

**注意**：这套轴名、象限命名、精确词汇表都是产品团队假设，**Sprint 结束前需做 5 人访谈校准**（见 § 8 开放问题）。

#### 4.3.2 组件状态

BodyMap 是**同一个组件**，在不同上下文有不同状态：

| 状态 | 上下文 | 交互 |

### 4.6 Pose Picker `pages/pose-picker`（P0，新增）

**入口**：`pages/record` → 点击"体式"字段 → **直接进入 picker**（不再有"我想找体式"中间按钮）

**页面结构**（三条路径合流在一个页面里，从上到下）：

1. **顶部搜索框** —— placeholder：`直接搜体式名？`；知道名字的用户走这条
2. **家族 tab 栏** —— `全部 / 前屈 / 后弯 / 扭转 / 侧弯 / 平衡 / 倒立 / 中正` 共 8 个 tab；可切换过滤
3. **候选卡片墙** —— 根据 tab 状态 + record 页已选部位上下文动态展示
4. **底部** —— `找不到？自定义命名` 按钮

**智能默认视图（关键）**：

| 上下文 | 默认 tab | 卡片墙展示 | 用户体验 |
|---|---|---|---|
| record 页**已选部位**（最常见路径）| `全部` | 与该部位相关的候选体式（跨家族，按相关度排）| **1 步到候选** |
| record 页**未选部位** | `全部` | 常见基础体式 12-15 个（战士式、下犬式、桥式、船式等）+ 引导语"或按家族浏览" | 一步概览常见项 |
| 用户主动点某家族 tab | 该家族 | 该家族全部体式（如已选部位，再交集过滤）| 按家族浏览 |
| 用户在搜索框输入 | 保持当前 tab | 匹配的体式实时过滤 | 快速定位 |

**每张卡片显示**：
- 体式图（GIF 优选，静态图兜底）
- 中文名 + 英文名（小字）+ 家族标签（角标）
- 主要激活肌群 2-3 块（简短文字，配色一致于 BodyMap 高亮色）
- Tap 卡片 → 选中并返回 record 页；长按卡片 → 预览体式详情（不离开 picker）

**兜底："找不到？自定义命名"**：
- 底部按钮 → 弹出输入框 → 用户输入自定义名（如"教练说的那个扭转"）
- 保存到用户个人体式库（P1；v2 先做基础记录）
- 自定义体式会在下次 picker 中显示为"我的体式"分组

**性能**：卡片墙首屏 8-12 张，滚动加载；GIF 首帧优先渲染，滚出屏暂停动画

**边界**：
- 用户搜索无匹配 → 展示"没有匹配的体式，用自己的话记下来？" + 引导到自定义命名
- 从 picker 返回 record 页时，体式字段自动填充；再次点体式字段可重新进 picker 修改

### 4.9 新手引导 · Onboarding（P1，横切）

**设计原则**：
- **每屏解决一件事**——不做连续 walk-through
- **触发式，不做统一欢迎流**——用户第一次触达每个关键交互时才出现对应 tips
- **默认可跳过 + 记住偏好**——一旦跳过或看过，不再显示；可在设置页重开
- **文案遵循原则 6**（观察式）——不用"太棒了"、"加油"、"欢迎"这类词

**3 个触发点**：

#### 触发点 1：首次进入 `pages/record`

一屏 tips，遮罩其余 UI：

- 标题：`你的第一次记录`
- 正文：
  - `在这里，你可以留下：`
  - `· 身体今天哪里被唤醒了`
  - `· 老师说的发力点`
  - `· 一句只属于你自己的感受`
  - `最少一个字段，就是完整的一条。`
- 按钮：`[跳过]  [知道了]`

#### 触发点 2：首次点击 BodyMap 上的肌肉（在 record 上下文）

半屏 tips，浮在肌肉选择弹层上：

- 标题：`点选肌肉`
- 正文：
  - `你可以标注这里的感受：`
  - `酸 / 紧 / 温 / 涨 / 无感`
  - `同一次记录可以标多块。`
- 按钮：`[知道了]`

#### 触发点 3：首次进入体式详情页

一屏 tips：

- 标题：`这是一份识别参考`
- 正文：
  - `· 上方的人体图 = 主要激活肌群`
  - `· 发力感线索 = 帮你找到觉察`
  - `· 常见代偿点 = 提醒你留意`
  - `这不是教程。想学怎么做，去线下课。`
- 按钮：`[知道了]`

**技术实现**：
- `profiles` 表新增 `onboarding_seen`（JSON 数组），记录已看过的引导 id（例：`["record", "bodymap_annotate", "pose_detail"]`）
- 客户端读取字段，未看过才显示
- 设置页有"重新体验新手引导"入口，一键清空该字段

**未来可扩展的触发点**（v3+）：
- 首次进入回顾页
- 首次导出图卡
- 达到第 50/100 节课的里程时

## 五、数据模型变更

**新增表**：

- `muscles` — 30 块肌群的字典表（id, 中文名, 英文名, 位置, 主要作用, 前后视, 深浅层）
- `pose_muscle_map` — 体式 ↔ 肌肉的多对多关系表（pose_id, muscle_id, is_primary, activation_strength）
- `muscle_sensation_map` — 用户每条记录里的肌肉级感受标注（entry_id, muscle_id, sensation_tag, note）
- `poses` — 独立体式表（原 v1 的 knowledge 表可能可以合并或替换）

**扩展现有表**：

- `diary_entries` 增加：`sensation_coord`（`{x: float, y: float}`，值域 `[-1, 1]`，可为 null 表示未选）、`sensation_words[]`（用户从候选胶囊选中的词 + 自由输入的词，最多 3 个）、`session_number`（累积课时序号）、`activation_note`（发力感 / 老师的重点，多行文本）

> 备注：象限名（舒展/饱满/过载/未启）可从 `sensation_coord` 派生，不单独存储字段。展示层需要象限名时按坐标计算即可。
- `body_annotations` 从"部位级"迁移到"肌肉级"（数据迁移脚本必要，或旧数据保留但字段废弃）
- `profiles` 增加：`onboarding_seen`（JSON 数组，记录已看过的引导 id）

**发力感字段的关联逻辑**：
- 若 `diary_entries.activation_note` 非空且该条记录关联了某个 pose_id，则该 note 在体式详情页可作为该体式的"我的发力感笔记"聚合视图之一
- 聚合视图 = 该体式历史所有 activation_note 的时间倒序列表
- 无需新增关联表，通过 `diary_entries` 反查即可

**新增 Storage bucket**：

- `entry-media` — 用户上传的图片、语音、手写扫描（私有权限）

**RLS 策略**：全部按 user_id 隔离，参考 v1 `006_create_rls_policies.sql` 的模式。

**迁移**：需新增一批 `008_muscle_atlas.sql` / `009_expand_diary_entries.sql` / `010_pose_muscle_map.sql`。
